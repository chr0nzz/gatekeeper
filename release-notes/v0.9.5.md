# v0.9.5

> **Pre-release.** One interface and documentation correction, no functional change. There is no reason to upgrade from v0.9.4 unless the client icon field misled you as well.

---

## Client icons

The icon field on an OIDC client said an icon would be detected automatically if you left it blank. Nothing ever did that. Leaving it blank produced a client with no icon and no explanation, so the only way to discover the truth was to give up and paste a URL by hand.

The field now describes what it actually does.

- **Consistent wording in all three places** a client icon can be set: the new client form on the Clients page, the one on the Dashboard, and the edit form. The edit form previously offered no guidance at all.
- **Finding an icon.** [selfh.st/icons](https://selfh.st/icons/) covers most self-hosted applications. Search for the application, copy the image address, and paste it in.
- **A limitation that is now written down.** An icon hosted only on your internal network cannot be used. GateKeeper downloads the image when you save, and outbound requests to private and loopback addresses are refused by the protection added in v0.9.2. [Managing clients](https://gatekeeper.xyzlab.dev/admin/managing-clients) explains this.

Automatic detection was considered and dropped. Deriving an icon from the application's own address would fail for exactly the self-hosted applications this is aimed at, since those addresses are usually private, and it would fail silently again.

## Upgrading

```bash
docker compose pull
docker compose up -d
```

No configuration changes and no migrations. Existing client icons are untouched.
