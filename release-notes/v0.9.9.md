# v0.9.9

**Security release.** Upgrade from any earlier version.

---

## Passkey and QR sign-in now run every login check

Signing in with a passkey or a QR code skipped checks that password sign-in applies. Both now go through the same checks.

- **Disabled accounts** can no longer sign in with a passkey.
- **App access policies** are enforced. A user outside an app's policy gets the access denied page instead of a sign-in to that app.
- **Forced password changes** apply. A user flagged by an admin is sent to change their password first.

## Deleting a user removes their passkeys and links

Deleting or rejecting a user now also removes their passkeys, social logins, sessions, trusted devices, group and policy memberships, and app tokens. A passkey left over from a deleted account no longer signs in. Leftovers from accounts deleted before this release are cleaned up on upgrade.

## Social login no longer links to an existing account on its own

When a social login's email matches an existing account, GateKeeper now asks the user to sign in to that account first. The social login is linked once that sign-in succeeds, within 10 minutes.

Users who only ever signed in through social login and have no password can set one with **Forgot password**, or use an email code if passwordless sign-in is on for them.
