# v0.9.6

The audit log now records how each sign-in actually happened, and a misleading email is fixed.

---

## Honest sign-in labels

Every sign-in in the audit log was labelled **Password** unless it used a passkey or a social provider. The completion step wrote one generic event no matter how the user authenticated, and the label was derived from that event alone. Opening an application while already signed in wrote the same event, so signing into a website through OIDC appeared as a password login even though nothing was typed.

The method now travels with the sign-in and the label follows it:

| Sign-in | Was labelled | Now labelled |
|---|---|---|
| App opened with an existing session | Password | SSO |
| Passwordless email code | Password | Email OTP |
| Trusted device | Password, twice | Trusted device, once |
| Social provider via OIDC | Social and Password, two rows | Social, one row |
| QR code | no label | QR code |
| Password (with or without a second factor) | Password | Password |

The duplicate rows also inflated the dashboard's sign-in counts, so those become accurate too. The audit page has filter chips for the new labels. Entries written by earlier versions keep their old labels.

## The wrong email on a duplicate registration

Trying to register with an address that already has an account sent that address a message headed "Password changed", telling the recipient their password had just been changed and to contact their administrator immediately. Nothing had changed. The subject was right, the body was the password-changed template. It now says an account already exists and that no action is needed.
