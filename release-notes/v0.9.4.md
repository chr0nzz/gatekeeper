# v0.9.4

Mobile apps can now sign in, the password policy is applied everywhere it should have been, and three things that were documented but not actually happening now do.

---

## Mobile app sign-in

An application that is not a website receives its authorization code on an address like `app.immich:///oauth-callback` rather than an `https://` one. GateKeeper refused those, so the Immich phone app, and anything else built the same way, could not complete sign-in.

A client that registers such an address is now treated as a native application, which is what permits it. Nothing needs switching on. Clients that only use `http` or `https` are unaffected, and the address is still matched exactly against the registered list, so this widens the kind of address allowed and never the set of destinations.

Native clients are normally held to stricter transport rules that would have rejected a plain `http://` address on a local network. Those keep working, so an app reached over plain HTTP at home can still offer both web and mobile sign-in.

There is a full [Immich guide](https://gatekeeper.xyzlab.dev/integrations/immich) covering both.

## Password policy is enforced everywhere

The password rules in Settings only applied to passwords users chose for themselves. Every administrator path skipped them.

An administrator could create an account, set someone's password, add another administrator, or change their own password using anything at least 12 characters long, even with the policy set to 20 with symbols required. The forms also advertised a fixed minimum of 12 regardless of what was configured.

All of those paths now check the configured rules, and every password field states and enforces the real minimum. The hint under the setting said "Minimum 8", which read like the policy in force rather than the lowest value that can be configured.

## Slide-in panels

Dialogs containing a form now arrive as a panel from the right instead of a box in the centre of the screen. On a wide display the page moves aside to make room rather than dimming, so the list you were working from stays readable. Below 1440px they cover the page as before. Escape closes them either way.

## Client test dialog

Four separate problems, all of which made it misleading:

- The **Open auth flow** link pointed at `/oauth/authorize`, which is not a route this server serves, so it always returned 404. It now uses `/authorize`, and the redirect address is encoded so one carrying its own query string is no longer mangled.
- The **access policy** was read from a table that does not exist. The query failed silently and every client was reported as open to all users, even ones restricted by a policy.
- **Passing checks were invisible.** The tick used a colour that is not defined in the stylesheet, so a client that passed every check showed a dialog of blank rows.
- The dialog now also lists the client's **redirect URIs** and says whether it counts as a **web or native** application.

## OIDC signing key rotation

The documentation has always said the signing key rotates every 30 days. It did not. The key was created on first run and kept forever, because nothing ever triggered a rotation.

GateKeeper now checks hourly and replaces the key once it is 30 days old, with no restart. The retired key stays published in the JWKS for another 48 hours, far longer than the 15 minute lifetime of the tokens it signed, then it is deleted. System health on the dashboard shows when the current key was last rotated and the date the next one is due.

Your existing key is already older than 30 days, so it will rotate within an hour of upgrading. Tokens issued beforehand keep working.

## TOTP recovery codes

Redeeming a recovery code wrote to the database while a query cursor was still open. GateKeeper uses a single database connection, so the write waited for a connection that could never be released and the request hung until it timed out. This affected every previous version and was found by the new tests.

## Documentation

- A new [home page](https://gatekeeper.xyzlab.dev) with a feature tour.
- A [screenshot gallery](https://gatekeeper.xyzlab.dev/screenshots) of every page, in both themes, following whichever theme you are reading in.
- Phone and tablet screenshots, captured by a script that now lives in the repository under `scripts/` along with the demo data it uses.
- `.env.example` listing every environment variable, kept honest by a test that fails when a new one is added to the configuration without being documented.

## Tests and tooling

The suite grew from 105 tests to over 250 and now covers the user-facing and administrator handlers, audit logging, webhook delivery, mail and social sign-in, alongside what was already covered. Several of the fixes above exist because writing those tests surfaced the bug.

`golangci-lint` and a formatting check run on every push, the documentation site is type checked and built in CI, and a Renovate configuration keeps Go modules, npm packages, workflow actions and container base images current.

---

## Upgrading

```bash
docker compose pull
docker compose up -d
```

No configuration changes and no migrations to run by hand.
